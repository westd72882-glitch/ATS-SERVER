# Anode Tanks Simulator (ATS) — защищённая сборка APK

## Самый быстрый старт

Залей репозиторий на GitHub → вкладка **Actions** → **Build signed & obfuscated APK** →
**Run workflow**. Больше ничего делать не нужно — если секреты (см. ниже) не заданы,
пайплайн сам сгенерирует одноразовый ключ шифрования и self-signed keystore прямо
в job'е. Через пару минут в разделе **Artifacts** будет готовый `ats-release-apk`,
который можно установить на телефон. Для постоянной подписи/ключа (например, публикация
в Google Play) один раз добавь секреты — см. раздел ниже.

Пайплайн оборачивает веб-игру в Android APK через **Capacitor**, при сборке:

1. **Обфусцирует** весь игровой JS (`javascript-obfuscator`: control-flow flattening, dead code injection, string array + RC4, self-defending, анти-debug).
2. **Шифрует** все `.glb`-модели AES-256-GCM; расшифровка — в рантайме через WebCrypto, **один раз на экране загрузки**, а не каждый кадр — поэтому на игровой FPS она не влияет вообще.
3. Ключ расшифровки **не встраивается в JS-бандл**. Он генерируется прямо в нативном Android-коде (кастомный Capacitor-плагин `AssetKey`, ключ раздроблен на части и XOR-замаскирован) и отдаётся JS только по запросу через bridge в момент расшифровки конкретной модели. Чтобы достать ключ, мало прочитать (даже деобфусцированный) JS — нужно ещё декомпилировать скомпилированный и обработанный R8 native-код.
4. Собирает release-APK с **R8/ProGuard** (minify + shrink resources).
5. **Подписывает** APK вашим release-keystore (хранится только в GitHub Secrets, в репозиторий не попадает) — либо одноразовым self-signed, если секретов нет.
6. Публикует APK в **GitHub Releases** при пуше тега `vX.Y.Z`.

⚠️ **Важно понимать границы защиты.** Любое клиентское Android/веб-приложение теоретически можно
декомпилировать и отреверсить — абсолютной защиты "чтобы вообще никто не взломал" не существует.
Этот пайплайн делает взлом **дорогим и неудобным** (обфускация, шифрование ассетов, анти-debug,
заминированный зашифрованный ключ), но не гарантирует 100% неприступность, как и любой другой
коммерческий протектор (DexGuard и т.п.).

## Что нужно сделать один раз (для постоянной подписи/ключа, необязательно для теста)

### 1. Сгенерировать ключ шифрования ассетов

```bash
openssl rand -hex 32
```

Сохраните результат как секрет **`ASSET_KEY`** в репозитории
(Settings → Secrets and variables → Actions → New repository secret).

### 2. Сервер и база на Render (бесплатно, этапами)
**База:** render.com → New → PostgreSQL → Name `ats-db`, Plan Free → Create. Дождаться Available, скопировать **Internal Database URL**.
**Сервер:** New → Web Service → репозиторий. Name `ats-server`, Root Directory `server`, Runtime Node, Build `npm install`, Start `node server.js`, Plan Free. В Environment Variables добавить `DATABASE_URL` = Internal URL базы → Create Web Service.
**Проверка:** в Logs `PostgreSQL: загружено записей 0` и `ATS server up, version 1.2.0`; адрес сервиса в браузере даёт `{"ok":true,...}`. Если в Logs «режим файла» — переменная `DATABASE_URL` не задана.
**Не засыпать:** uptimerobot.com → HTTP(s) монитор на `https://<адрес>/health`, интервал 5 минут.
**Когда база истечёт (~30 дней):** создать новую, в Environment заменить `DATABASE_URL`, Manual Deploy → Restart. Старые данные не переносятся (при необходимости заранее `pg_dump`).

### 3. APK
1. GitHub → Settings → Secrets and variables → Actions → **Variables** → `API_URL` = адрес сервера Render.
2. Секреты подписи (`ASSET_KEY`, `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`) — см. выше.
3. Actions → *Build signed & obfuscated APK* → Run, либо `git tag v1.2.0 && git push origin v1.2.0`.
4. Новая версия: `node scripts/bump-version.js 1.3.0` → push (Render задеплоит сервер) → дождаться деплоя → тег для APK. Версии сервера и APK обязаны совпадать.

### 4. Что теперь делает СЕРВЕР (авторитетный бой)
Клиент в мультиплеере шлёт только ввод (положение, углы башни, «выстрел»). Всё остальное решает сервер (`server/combat.js`):
- **Танк и уровень** берутся из аккаунта: нельзя встать в очередь на танке, которого нет (проверка `own`).
- **Положение:** лимит скорости по характеристикам танка (+45% запас), границы арены, сбитая гусеница = стоишь 7 с. Нарушителя сервер возвращает назад (`corr`).
- **Перезарядка и обоймы** (AMX 50 B, FV4005) считаются на сервере; выстрел раньше времени игнорируется.
- **Выстрел:** сервер строит луч от орудия по реальным углам, с разбросом, проверяет попадание по хитбоксам с перемоткой на задержку игрока, считает зону брони, угол, рикошет, пробитие и урон (разброс 0.85–1.15). Попадание в низ борта = сбитая гусеница.
- **HP, смерти, киллы, итог боя** (победа/поражение/таймаут 15 мин, выход = поражение) и **награда** — только сервер, сразу пишется в Postgres и приходит клиенту (`end`).
- **Карта** выбирает сервер и шлёт всем одинаковую. Урон по клиентам больше не считается локально.
- **Бои с ботами** (идут на клиенте): перед боем сервер выдаёт одноразовый билет; награду за бой с ботами можно получить только по билету, с проверкой «урон и киллы не больше, чем физически успел нанести танк за время боя», минимум 20 с. Прежняя дыра с `leave`-наградой и произвольным `dmg` закрыта.
- **Экономика** (покупка, продажа, исследование, промокоды, задания, почта) — на сервере и сразу сохраняется в БД. Исправлено: продажа танка раньше не сохранялась до следующей записи.
- Защита от флуда по WebSocket: больше 50 сообщений в секунду — отключение.

Характеристики танков сервер берёт из `server/tanks.json`. После **любого** изменения `CATALOG` в `www-src/js/04-tank.js` выполни `node scripts/sync-tanks.js` и закоммить файл.

### 5. Честные ограничения
- **Препятствия карты сервер не знает:** выстрел через дом/дерево сервер засчитает (визуально снаряд клиента упрётся). Чтобы закрыть: вынести `cols` карт в JSON для сервера (следующий шаг).
- Хитбокс танка на сервере — упрощённый прямоугольник от длины корпуса (`len`); если попадания «проходят мимо» или наоборот, подстрой `box()` в `combat.js`.
- Разброс снарядов на сервере свой (`SPREAD`, по умолчанию .005 рад, env-переменная), не равен клиентскому визуальному.
- Один экземпляр сервера (кэш в памяти + запись в БД); для нескольких экземпляров нужна отдельная доработка.
- Бои с ботами не авторитетные по природе (боты на телефоне): билет лишь ограничивает возможный выигрыш.

### 6. Локальная отладка
`cd server && npm i && PORT=3000 node server.js` — без `DATABASE_URL` работает в файловом режиме. С Postgres: `DATABASE_URL=postgres://... node server.js`.
